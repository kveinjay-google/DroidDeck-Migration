# Project Documentation

Create and use these subdirectories as needed for documentation that requires more detail than the repository-level files provide.

- Use `specs/` for approved requirements and feature specifications.
- Use `plans/` for implementation and migration plans.
- Use `ops/` for operating procedures and maintenance guidance.
- Use `decisions/` for architecture and technical decision records.
- Use `deploy/` for deployment procedures and environment notes.
- Use `troubleshooting/` for symptoms, diagnoses, and verified recovery steps.
