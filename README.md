# DroidDeck 迁移版

基于 Droid-Deck/DroidDeck 0.4.0 提交 `10ef8c4bd62b21872fc13382a808cb0f2f117b26` 的个人分支，加入无需电脑或 Root 的 Android 备份与恢复。

- 独立包名 `com.droiddeck.migration`，与官方版并存。
- 旧 TAR + 可选设置 JSON；新格式为清单和每卷最多 2,000,000,000 字节的分卷。
- 个人备份保留私有游戏与存档；运行环境分享包过滤账号、存档、浏览器缓存、日志、设备标识及个人设置。
- 完整校验后恢复到临时目录，保留 Linux 链接、执行权限与回滚副本。
- 原官方版数据不受影响；备份只读取迁移版本自身目录。

## 在手机上使用

1. 安装迁移版 APK，允许安装未知来源应用。
2. 将所有分卷和 `backup.ddbackup.json` 放在同一个文件夹。
3. 打开迁移版，选择“恢复分卷备份”，在系统文件选择器中选中该文件夹并确认恢复。
4. 等待完整性检查与恢复两遍处理。留出至少备份解包大小加 1 GiB 的额外空间；现有迁移版环境会保留为回滚副本。
5. 恢复完成后关闭应用，从手机桌面重新打开，再进入 DroidDeck。
6. 登录账号，核对驱动和系统子进程限制。共享目录/SD 卡中的独立游戏文件需另行复制。

“个人备份”仅供自己换机，可能包含游戏和存档中的私人信息，不能视为纯净分享包。“运行环境分享包”仅保留软件路径，不含个人设置和存档。所有分卷须一起传输，不需要先合并成大 TAR。

## 构建

Android SDK34、Java17、Gradle8.11.1。基于已验证、同提交的原 APK 原生库与资产编译管理代码，未重新编译原生游戏引擎。原生库逐文件 SHA256 在每次打包时校验，清单见 `tools/migration/native-origin.json`。

本地构建脚本 `tools/migration/build.py` 将 Gradle缓存、输出、日志和临时文件放在外置卷，限制两个 Gradle workers。签名文件和密码保存在外置构建目录，未提交。要在另一台机器构建，需要自行生成签名并调整 SDK、Gradle及构建目录；后续升级必须使用同一签名。

完整源码和上游归属遵循 GPL-3.0；见 `LICENSE` 与 `docs/UPSTREAM_README.md`。Steam与Proton属于Valve，备份软件资源的使用权和账号登录仍由用户自行管理。

### 准备原生构建输入

本仓库不保存手机备份、运行环境分卷或签名私钥。此管理代码分支使用官方 0.4.0 APK 的原生库；先从上游 Release 获取标准 DroidDeck-0.4.0.apk（不是 antutu/ludashi/pubg 变体），确认 SHA256 为 `9df9e89a0b34e5f96ae8050640f86f2e15e3876030b484343dd2039574aea5bf`。

从该 APK 解出 `lib/arm64-v8a/*.so` 到 `app/src/main/jniLibs/arm64-v8a/`，按 `runtime-payload-origin.json` 的清单将对应 `assets/` 文件解到 `app/src/main/assets/`。保留本仓库用于独立套接字的 shim，Gradle 负责组合原资产与更新后的脚本；每次打包校验 `native-origin.json` 与 `runtime-payload-origin.json`。不要导入原 APK 的 dexopt 配置。构建输出路径和签名由本地脚本配置；首次构建请调整 `build.py`、根目录 `build.gradle`、`verify_native.py` 和 `app/build.gradle` 中的外置盘路径以符合自己的环境。

## 导入失败时导出日志（migration.2 起）

失败后点击“查看上次日志”查看原因，或点击“导出诊断日志”，在系统文件选择器中保存为 `.txt`。日志关闭应用后仍保留，最近五次任务各保存一份。报告记录导入模式、版本/Android信息、所选文档、分卷预期及实际大小、SHA256失败详情、处理阶段、空间、归档条目/拒绝规则/字节位置和异常链。不记录设置值、归档文件内容；JSON错误内容隐藏。日志可能包含设备型号和个人文件名，分享前请检查，不会自动上传。

`Unsafe archive path` 现在会指出具体条目与绝对路径、上级目录等触发规则。此版本增加诊断，不代表此前截图中的未知根因已经修复；请用新版重试一次并导出失败报告。

## Linux 文件名兼容修复（migration.3）

按 Android/Linux 的 POSIX 路径语义导入：只有 `/` 是目录分隔符，反斜杠、冒号、中文等均作为文件名原样保留，不按 Windows 命名习惯过滤，不对 systemd 的 `\x2d` 名称解码或改名。修正 migration.2 对正常 systemd 文件的误拒绝，并避免导出时静默过滤同类文件。仍限制写入目标目录内，拒绝真正的绝对路径、`../` 越界及不安全的链接布局。已有备份无需改名或重新打包，直接覆盖升级 APK 后重试。
